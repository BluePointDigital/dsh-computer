## Canary-discovered bug and fix

v0.1.9 passed scratch-front verification but the actual installed DSH panel's
frame failed with ERR_EMPTY_RESPONSE. The HTTP proxy treated a normal upstream
request close as an incomplete frontend response; DSH asynchronously compresses
responses, so writableEnded was not yet set. v0.1.10 tracks upstream response
completion separately and preserves normal completed responses during carrier
compression. Added deterministic compression regression; 21 Node tests and 35
proxy checks passed before publishing v0.1.10. v0.1.9 is not recommended for rollout.

## Restart recovery

Director's second container restart exposed stale nested containerd runtime state
(timeout waiting for containerd). No live dockerd/containerd process remained.
The resolved volatile directory `/run/docker/containerd` was preserved as
`/run/docker/containerd.stale-v019-20261012-1920`; `/var/lib/docker` was untouched.
The nested daemon was restarted through Portainer exec. A stopped nginx runc
runtime record was removed only after its state was verified stopped, then the
existing desktop/nginx containers were started. No app was recreated and no data
volume was removed. This was a runtime recovery, not a DeepSeek core code patch.

## Remaining verification

Public `https://director.bluepointdigital.com/` is reachable with a valid TLS
certificate but returns NPM Basic Auth **401** to the test client. Existing NPM
proxy has WebSocket upgrades enabled. The saved NPM admin credential did not
match its access list; no auth policy was weakened or changed. Need an authorized
Director Basic Auth password (username bpdigital is listed) to exercise the same
panel over public HTTPS/wss, ideally from an off-tailnet browser.

The verifier now supports `--public`: it removes internal DNS overrides, uses
normal public HTTPS resolution and certificate validation, and answers only
Director's server Basic Auth challenge through CDP. Supply the credential as
`DIRECTOR_BASIC_AUTH_PASSWORD` in a secure process environment, optionally
`DIRECTOR_BASIC_AUTH_USERNAME` (default bpdigital). It travels to the isolated
browser over stdin, not command arguments or committed files. The public mode
has not been run successfully yet because no authorized credential is available.

HyperFrames-specific JS rewriting has not been verified on this canary; its
existing container was already stopped during runtime inspection and was not
started or altered. Wider deployment remains intentionally paused pending public
HTTPS verification. All source/deployment findings here distinguish internal
GUI success from public-path success.
